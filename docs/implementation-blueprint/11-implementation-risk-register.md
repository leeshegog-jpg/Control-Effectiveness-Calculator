# 11 — Implementation Risk Register
**Status: DRAFT — Phase 2.1 Implementation Blueprint. Baseline: Design Baseline v1.0 (frozen).**
**Scope:** risks to *implementing* the approved architecture — not a re-assessment of the architecture itself (that risk surface was addressed in Design Baseline v1.0). Each risk below traces to a specific design-doc control already in place, or names the gap where one isn't.

## Security Risks

| ID | Risk | Cause | Consequence | Controls | Owner | Verification method |
|---|---|---|---|---|---|---|
| S1 | Client-side LLM API key exposure | Reintroducing V1's own defect (`OHS_Command_Centre/hazard_register.html`, architecture §1.4 finding 3) under implementation pressure | Anthropic API key harvestable from browser, billing/abuse exposure | Server-side-only key architecture already fixed in design; PR secrets-in-diff scan + pentest regression test ([08-testing-strategy.md](08-testing-strategy.md) §8) | Backend + Security | Pentest sign-off before Prod go-live, repeated per major release |
| S2 | Over-broad AuthZ scopes | Rapid module delivery skips fine-grained role definition | A general user able to perform ontology-curator-only actions (publishing concepts) or approve their own Safety Case claims | Entra ID role review checklist ([10-operational-readiness-checklist.md](10-operational-readiness-checklist.md)) | Security + Platform Eng | Role/scope audit before each environment promotion to UAT/Prod |
| S3 | Document upload attack surface | AI Document Intelligence Engine accepts arbitrary PDF/DOCX/XLSX uploads | Malicious file processing (parser exploits), oversized-file DoS | Parsing sandboxed in the Ingest Service container ([PLATFORM_ARCHITECTURE_V2.md](../PLATFORM_ARCHITECTURE_V2.md) §2); file-size/type validation at upload | Backend + Security | Security test suite includes malformed-document cases |
| S4 | Contract declares `bearerAuth` but the implementation does not enforce it | The frozen `10-openapi.yaml` sets `security: [bearerAuth]` globally; the R1 implementation (Milestones 0–3) ships no authentication middleware — every implemented operation responds to unauthenticated requests. Surfaced by the Schemathesis contract suite (PR #44), which reports `MissingHeaderNotRejected` on all 113 operations | An unauthenticated caller can exercise every implemented endpoint (read and write) in any environment where the app is reachable; a regulator-facing or UAT deployment would expose safety data without an access control the contract claims exists | Documented, not silently carried: the contract suite deliberately **disables** its auth-conformance checks against this gap ([ADR-007](../../.adr/ADR-007-contract-test-suite-scope-and-ci-treatment.md) D2) rather than masking it with a token the app ignores; authentication enforcement is its own governed implementation slice, at which point ADR-007's auth checks are re-enabled. Relates to S2 (AuthZ scopes) — S4 is authN, S2 is authZ | Security + Backend + you (approver) | Authentication-enforcement slice GO'd and implemented before any UAT/Prod promotion; ADR-007 auth-conformance checks re-enabled and green as the verification that the gap is closed |

## AI Risks

| ID | Risk | Cause | Consequence | Controls | Owner | Verification method |
|---|---|---|---|---|---|---|
| A1 | Extraction hallucination on a critical item | LLM fabricates a plausible-sounding critical control or SFAIRP justification | A fabricated fact enters the Safety Case chain | Critical-item override — always `flag-for-review`, never auto-accept, for critical controls/SFAIRP/notification determinations ([04](../knowledge-graph/04-ai-extraction-specification.md) §6) | AI/Backend + HSE reviewer | Every critical-item extraction traced to a human approval in provenance ([05](../knowledge-graph/05-knowledge-provenance-model.md)) |
| A2 | Demonstration narrative unsupported by cited facts | Generation pipeline drifts from the constrained-narration discipline | A Demonstration reads plausibly but overstates what the graph actually shows | Every claim in `generated_narrative` must cite a `source_fact_refs` entry ([11](../knowledge-graph/11-safety-case-demonstration-model.md) §7.3); never auto-publishes | AI/Backend + HSE reviewer | Manual review at `draft → reviewed` transition checks every citation resolves to a real fact |
| A3 | Stale Demonstration presented as current | Underlying facts change after a Demonstration is approved/published | Regulator shown an outdated argument | Staleness detection rule R16 ([07-inference-rules-catalogue.md](../knowledge-graph/07-inference-rules-catalogue.md)) | AI/Backend | Staleness flag tested against a live entity-update scenario before R7 exit |
